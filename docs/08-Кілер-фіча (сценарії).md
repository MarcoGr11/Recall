# Ключова відмінна фіча (killer feature)

**Сценарний симулятор рішень (branching-сценарії) з AI-генерацією чернеток**

Замість лінійних тестів — інтерактивний сценарій з розгалуженнями, що поєднує кілька модулів одразу (наприклад: тактика + медицина + зв'язок в одному кейсі). Курсант на кожному кроці обирає дію, вибір веде до наступного кроку; в кінці — розбір усього шляху з поясненням, де і чому сталась помилка.

Жоден з існуючих аналогів не пропонує цього — див. [[12-Аналіз аналогів]]. Це головний аргумент актуальності теми диплому.

## Конвеєр генерації та курації контенту

1. Інструктор вручну ініціює генерацію: обирає модуль ([[07-Навчальні модулі]]), тему, рівень складності
2. Backend кладе завдання в чергу (**Redis + BullMQ**), а не викликає Claude API синхронно — інструктор одразу отримує відповідь "запит прийнято", не чекаючи генерації
3. Воркер асинхронно забирає завдання з черги, викликає Claude API (Haiku 4.5), парсить структурований JSON, записує чернетку в БД зі статусом `draft`
4. Інструктор бачить нову чернетку в черзі модерації (список/сповіщення) — схвалює / редагує / відхиляє
5. Тільки після підтвердження (`approved`) сценарій стає доступний курсантам

**Чому черга, а не прямий виклик**: генерація займає кілька секунд, і синхронне очікування блокує запит інструктора. Черга також дає природний механізм повторних спроб (retry) при збоях API та контроль паралельних викликів (rate limiting з боку самого застосунку, не тільки з боку Anthropic).

Автоматична (не ініційована інструктором) генерація — винесена за межі MVP, позначена як перспектива розвитку (напр. на основі слабких тем з SM-2). Технічно вона теж піде через ту саму чергу.

## Формат промпту

- Системний промпт (кешується): формат виводу JSON, стиль, один few-shot приклад готового сценарію
- Параметри запиту: модуль, тема, складність, кількість кроків, мова
- (Перспектива) слабкі місця конкретного курсанта — для прицільної персоналізованої генерації

## Пояснення результатів

Кожен вузол сценарію (крок) і кожна кінцівка містять коротке пояснення (`explanation` / `feedback_text`) — чому вибір був правильний/неправильний. Курсант після завершення бачить повний шлях своїх рішень з поясненнями по кожному кроку, а не тільки фінальний результат. Пояснення генеруються разом зі сценарієм і проходять ту саму модерацію.

## Показовий набір для диплому/захисту — 10 сценаріїв

| Рівень | Кроків | Кількість | Модулі (приклади) |
|---|---|---|---|
| Легкий | 3-4 | 4 | Домедична допомога (турнікет під вогнем), Зв'язок (передача координат), РХБЗ (сигнал тривоги), Статути (типова ситуація) |
| Середній | 4-7 | 4 | Тактична підготовка (дії при обстрілі), Домедична допомога (TFC — складніший кейс), Розвідка (виявлення БПЛА + рішення), Інженерна підготовка (виявлення міни) |
| Складний | 7-10 | 2 | Комбінований міжмодульний кейс (тактика + медицина + зв'язок в одному ланцюжку рішень) |

Два "складні" міжмодульні сценарії — найсильніший демонстраційний матеріал: показують системне мислення, а не запам'ятовування.

## Вартість генерації (Claude API)

- API окремий від Claude.ai/Pro-підписки, потрібен окремий ключ на platform.claude.com
- Нові акаунти отримують ~$5 пробного кредиту (безкоштовно, не потребує повернення)
- Студенти з .edu поштою можуть подати заявку на додаткові кредити (до $300)
- Генерація 10 показових сценаріїв на Haiku 4.5 ($1/$5 за млн токенів) — реалістично в межах $5 стартового кредиту
- Оптимізація на майбутнє: Batch API (-50%), prompt caching (до -90% на повторний контекст)

## Структура даних

Див. також [[11-Структура даних (ER)]]

```
scenario_templates: id, module_id, difficulty, generated_by (ai/human), status (draft/approved/rejected)
scenario_nodes: id, scenario_id, text, is_ending, outcome_type (success/injury/fail), explanation
scenario_choices: id, node_id, text, next_node_id, is_correct, feedback_text
generation_log: template_id, prompt_used, model_used, input_tokens, output_tokens, cost_usd, reviewed_by
generation_jobs: id, template_id (nullable до завершення), requested_by, status (queued/processing/done/failed), queued_at, finished_at
```
