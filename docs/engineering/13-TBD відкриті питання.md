## Зміни ухвалених рішень

- 24.11.2026 — токени листів: спільна таблиця `email_tokens` з ENUM `email_token_purpose` → дві таблиці `email_verification_tokens` і `password_reset_tokens` → рішення автора: окремі строки дії (24 год і 30 хв) і окремі правила одноразовості без поля-дискримінатора ([[11-Структура даних (ER)]], підрозділ 2.7 [2_design.md](../2_design.md)).
- 24.11.2026 — rate limit запиту відновлення доступу і повторного листа підтвердження: 3 запити/год на адресу і 20 запитів/год на IP → 5 запитів/год на адресу і 5 запитів/год на IP → рішення автора ([SRS-NFR-SEC-08](../srs.md#srs-nfr-sec-08), [[10-Безпека даних]]).
- 24.11.2026 — перевірка ролі в кімнаті Socket.io: роль і строк дії токена на кожній події кімнати → роль перевіряється під час приєднання, при вилученні учасника всі його з'єднання негайно виключаються з кімнати, строк дії токена перевіряється на кожній події без звернення до БД, після закінчення — подія `auth.expired` і розрив → рішення автора за результатами архітектурного аудиту (A-23, A-25): запит до БД на кожну подію 100 студентів не дає додаткового захисту порівняно з негайним виключенням ([SRS-FUN-44](../srs.md#srs-fun-44), підрозділ 2.1.1 [2_design.md](../2_design.md)).
- 24.11.2026 — перевірка працездатності: GET /health backend і worker — 200 лише за доступності PostgreSQL і Redis → backend: 200 за доступності PostgreSQL, стан Redis у полі `queue`; worker: PostgreSQL і Redis → рішення автора (A-19): без Redis тестування, план і моніторинг працюють, тому backend не повинен бути unhealthy ([SRS-NFR-OBS-02](../srs.md#srs-nfr-obs-02)).
- 24.11.2026 — узгодження PostgreSQL і Redis для задач генерації: лише при старті worker → щохвилини задачею черги maintenance (повторна постановка задач queued, старших за 1 хв) → рішення автора (A-21): «загублена» задача виявляється не пізніше ніж за 2 хв, а не до перезапуску worker ([ADR-001](../adr/0001-choice-of-technology.md), історія змін).
- 24.11.2026 — добовий ліміт вартості: сума фактичної вартості → сума фактичної вартості і резерву 0,024 USD на кожну задачу в станах queued і processing → рішення автора (A-22): без резерву одночасні постановки перевищують ліміт до 2,4 раза ([SRS-NFR-COST-02](../srs.md#srs-nfr-cost-02)).
- 24.11.2026 — резервне копіювання: лише pg_dump → pg_dump і архів тому з PDF → рішення автора (A-18): після відновлення БД не посилається на відсутні файли ([SRS-NFR-REL-03](../srs.md#srs-nfr-rel-03)).
- 24.11.2026 — перевірка обмежень текстового шару PDF (SRS-FUN-51): UploadMiddleware → CourseService через порт IPdfTextExtractor в окремому потоці `worker_threads` → рішення автора (A-05, A-11): бізнес-обмеження — у Core, вилучення тексту не блокує event loop.
- 24.11.2026 — архітектурний стиль: «модульний моноліт, модулі можна винести в сервіси, Backend API масштабується горизонтально» → модульний моноліт за Ports and Adapters, спільна схема, один екземпляр Backend API, вертикальне масштабування → рішення автора (A-02, A-07), зафіксоване новим [ADR-002](../adr/0002-modular-monolith.md).
- 24.11.2026 — реєстрація з уже зареєстрованою поштою: 409 `email-taken` → 202 і лист «обліковий запис уже існує» на цю адресу → рішення автора (аудит маршрутів N-12): 409 дозволяв перевірити існування облікового запису одним запитом в обхід захисту від user enumeration на вході і відновленні пароля ([SRS-FUN-01](../srs.md#srs-fun-01), OWASP A07:2021).
- 24.11.2026 — токен у посиланнях листів: query-параметр `?token=…` → фрагмент URL `#token=…` → рішення автора (N-13): фрагмент не надсилається на сервер, тому токен не потрапляє в журнал доступу Reverse Proxy, історію запитів і `Referer` навіть за відкриття посилання в браузері ([SRS-FUN-55](../srs.md#srs-fun-55)).
- 24.11.2026 — видалення облікового запису: `DELETE /me` лише за access-токеном → `POST /me/deletion` з поточним паролем у тілі → рішення автора (N-15): незворотна дія вимагає повторної автентифікації; OpenAPI 3.0.3 не визначає тіла запиту для DELETE, тому операцію оформлено як POST до підресурсу ([SRS-FUN-48](../srs.md#srs-fun-48)).
- 24.11.2026 — rate limiting: один RateLimiter до JwtAuthMiddleware з ключем userId → IpRateLimiter до перевірки токена (публічні операції, IP з `X-Forwarded-For`, `trust proxy` = 1) і UserRateLimiter після неї (ключ — `sub` перевіреного токена) → рішення автора (N-18, N-19): до перевірки токена userId не перевірений, а без довіри до проксі всі IP-ліміти рахувались би за адресою контейнера Caddy ([SRS-NFR-SEC-08](../srs.md#srs-nfr-sec-08), рис. 2.3).
- 24.11.2026 — заголовок `Location` у відповідях 201: для всіх створених ресурсів → лише для ресурсів з операцією GET (курс, спроба, задача генерації) → рішення автора (N-07): `Location` на ресурс без GET вів би на 404 або 405.
- 24.11.2026 — шифрування даних у спокої: шифрування чутливих полів БД і SQLCipher на пристрої → поля БД не шифруються на рівні застосунку, паролі й токени зберігаються як хеші, резервні копії шифруються `age`, токени на пристрої — у expo-secure-store з `WHEN_UNLOCKED_THIS_DEVICE_ONLY` → рішення автора (аудит AppSec S-32, S-33): декларація не мала алгоритму, ключа і переліку полів, а локальної бази даних у MVP немає ([[10-Безпека даних]], підрозділ 2.4 [2_design.md](../2_design.md)).
- 24.11.2026 — ліміт невдалих входів: 5 невдалих спроб/хв на обліковий запис → 5/хв на пару «поштова адреса + IP» і 100/год на адресу, у тому числі для незареєстрованих адрес → рішення автора (S-22): ліміт на обліковий запис дозволяв безстроково блокувати вхід власнику, а різниця 429/401 розкривала існування адреси ([SRS-NFR-SEC-08](../srs.md#srs-nfr-sec-08)).
- 24.11.2026 — ліміт за IP: лише публічні операції → глобальний ліміт 300 запитів/хв на IP для всіх маршрутів до розбору тіла і ліміти публічних операцій → рішення автора (S-20): запити з невалідним токеном не обмежувало ніщо.
- 24.11.2026 — строк дії refresh-токена: 30 днів від створення кожного токена → 30 днів від входу, ротація строк не подовжує, ротація під `SELECT … FOR UPDATE` → рішення автора (S-03): ковзний строк робив сесію безстроковою ([SRS-NFR-SEC-01](../srs.md#srs-nfr-sec-01), [SRS-NFR-SEC-02](../srs.md#srs-nfr-sec-02)).
- 24.11.2026 — глибина пагінації: `page` ≤ 10 000 → `page` ≤ 100 (глибина 10 000 записів) → рішення автора (S-15): OFFSET до 999 900 давав змогу перевантажити PostgreSQL одним запитом ([api/openapi.yaml](../api/openapi.yaml)).
- 24.11.2026 — валідація тіла: схеми zod з відкиданням невідомих полів → zod `.strict()` (невідоме поле → 400), явний перелік полів у репозиторіях, вихідні DTO → рішення автора (S-10, S-14): відкидання полів не захищало від Mass Assignment у шарі Outbound.
- 24.11.2026 — журнал аудиту: лише дії з контентом (ContentAuditLog) → також події безпеки: AuthService і PrivacyService залежать від IAuditLogRepository → рішення автора (S-31): enum `audit_action` містив `password_reset` і `token_reuse`, але жоден компонент їх не записував.
- 25.11.2026 — PKM-копія SRS: повна копія `srs.md` у `docs/24-Специфікація вимог (SRS).md` → картка з посиланнями на розділи `srs.md` → дві копії вимог розходилися після кожної правки і вимагали ручної синхронізації; єдине джерело правди — `srs.md`.
- 25.11.2026 — назва і статус модуля навичок: оцінна назва модуля в переліках функцій MVP нотаток 00–03 → «модуль базових інженерних навичок», напрям розвитку поза MVP; сценарний тренажер також прибрано з Must Have нотатки 03 → нотатки розходилися з рішенням 24.11.2026 (BR-09…BR-11, BR-15, [srs.md](../srs.md) §1.2), а попередня назва — оцінне слово (Vale).
