# Нефункціональні вимоги (NFR)

| ID | Категорія | Вимога | Критерій перевірки |
|---|---|---|---|
| NFR-01 | Performance | Основні екрани завантажуються швидко | Не більше 2 сек на стандартному з'єднанні |
| NFR-02 | Role-based Security | Кожна роль має доступ лише до дозволених даних | Студент не бачить чужі результати; co-instructor не може видалити курс; прямий запит до чужого ресурсу повертає 403 |
| NFR-03 | Reliability | Результати тестів, SM-2-прогрес, сценарії не втрачаються | 100% збережених записів доступні після повторного входу |
| NFR-04 | Real-time | Дашборд викладача оновлюється без перезавантаження сторінки | Затримка WebSocket-оновлення не більше кількох секунд |
| NFR-05 | Data Security | Персональні дані захищені шифруванням і мінімізовані | HTTPS/WSS, шифрування чутливих полів; див. [[10-Безпека даних]] |
| NFR-06 | Compatibility | Коректна робота на різних Android-пристроях, включно зі старішими | Тестування на кількох версіях Android |
| NFR-07 | Cost Control | Вартість AI-генерації (сценаріїв і тестів) контрольована і логується | Кожен виклик логується (`generation_log`), у межах пробного/студентського кредиту |
| NFR-08 | Anti-cheating | Тести стійкі до списування | Рандомізація порядку питань і відповідей |
| NFR-09 | Content Upload | Завантаження лекційних матеріалів обмежене за розміром і типом файлу | Ліміт розміру файлу (наприклад, до 20 сторінок/N МБ); підтримка PDF та звичайного тексту в MVP |
| NFR-10 | Prioritization Correctness | Персональний план на день коректно поєднує пріоритети предметних тем (за датою іспиту) і evergreen-порції (стрік) | Формула розрахунку задокументована і покрита тестами на кількох сценаріях (різна кількість курсів, різна близькість дат) |
| NFR-11 | Dashboard Scalability | Heatmap і live-дашборд коректно працюють при типовому розмірі групи | Коректне відображення для групи до ~30 студентів без помітного уповільнення |
| NFR-12 | Accessibility — масштабування | Інтерфейс коректно відображається при збільшенні системного шрифту | Ручна перевірка при масштабі шрифту до 200 %: текст не обрізається, елементи не перекриваються |
| NFR-13 | Accessibility — читачі екрана | Усі інтерактивні елементи доступні для TalkBack (Android) і VoiceOver (iOS) | Кожна кнопка, іконка та листок дерева знань має текстову мітку і роль; ручний прохід ключових екранів з увімкненим TalkBack/VoiceOver |

Обсяг доступності свідомо обмежено двома вимогами (масштабування і читачі екрана). Інші критерії WCAG 2.2 (контраст, розмір зон натискання, зменшення анімації, подовжений час тесту) — напрям розвитку.
