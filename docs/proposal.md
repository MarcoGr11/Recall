# Thesis Proposal — Recall

Спеціальність F2 — Інженерія програмного забезпечення

## 1. Робоча назва проєкту

Українською: Платформа адаптивної підготовки студентів ІТ-спеціальностей
до сесії з пріоритизацією повторення за розкладом іспитів та сценарним
тренажером прийняття рішень.

Англійською: Recall — Adaptive Exam Session Preparation Platform for IT
Students with Exam-Schedule-Driven Prioritization and AI-Generated
Branching Decision Scenarios.

## 2. Актуальність та проблематика

Підготовка студентів ІТ-спеціальностей до сесії традиційно організована
через системи управління навчанням (Moodle та подібні), які забезпечують
лише одноразовий контроль знань: після складання тесту матеріал не
переглядається повторно, а результат не супроводжується механізмом
довгострокового утримання інформації. Дослідження ефекту інтервального
повторення (spaced repetition) демонструє, що одноразове тестування без
подальшого повернення до матеріалу не забезпечує стійкого закріплення
знань у довгостроковій пам'яті.

Наявні застосунки для інтервального повторення (Anki, Quizlet) вирішують
задачу індивідуального запам'ятовування, проте не надають інструменту
для викладача (немає ролі викладача з моніторингом групи в реальному
часі), не враховують одночасну підготовку до кількох дисциплін з різними
термінами складання та не перевіряють здатність застосовувати знання у
практичних ситуаціях, обмежуючись форматом питання-відповідь.

Проблема, що вирішується: відсутність програмного засобу, який поєднує
адаптивне повторення матеріалу, пріоритизоване за розкладом сесії між
кількома дисциплінами одночасно, з інструментами контролю засвоєння
матеріалу групою в реальному часі з боку викладача та перевіркою
практичного, ситуативного мислення через реалістичні сценарії прийняття
рішень.

## 3. Сформована ідея продукту

Тип архітектури: кросплатформний мобільний застосунок (React Native) з
клієнт-серверною взаємодією через REST API та WebSocket, backend-
монолітом з виокремленою асинхронною обробкою фонових задач через чергу
повідомлень.

Продукт реалізує курс-центричну модель управління доступом: користувач
із роллю засновника курсу створює навчальний курс за однією з дисциплін
навчального року, запрошує співвикладачів і студентів; роль користувача
визначається окремо в межах кожного курсу, а не глобально в системі.
Кожен курс має прив'язану орієнтовну дату складання (іспит/залік), що
використовується для міжпредметної пріоритизації повторення.

Типовий сценарій використання: один предмет — приблизно 15 лекцій.
Викладач завантажує лекції, кожна стає окремою темою курсу зі своїм
тестом, згенерованим через Claude API. Дата екзамену — орієнтовна
(вказує викладач приблизно, без прив'язки до офіційного розкладу сесії).

## 4. Детальний опис функціоналу (Core Features)

1. Реєстрація та рольова модель доступу (засновник курсу / співвикладач /
   студент) з розмежуванням прав на рівні кожного окремого курсу.
2. Проходження навчального матеріалу та тестів з рандомізацією порядку
   питань і варіантів відповідей.
3. Адаптивне повторення матеріалу за алгоритмом SM-2 з міжпредметною
   пріоритизацією: розрахунок оптимального інтервалу повторення теми з
   урахуванням кількості днів до складання відповідної дисципліни, що
   формує єдиний персональний план підготовки на день для студента.
4. Моніторинг прогресу групи викладачем у реальному часі через
   WebSocket-з'єднання, без необхідності оновлення сторінки.
5. Сценарний тренажер прийняття рішень: інтерактивні розгалужені
   сценарії на матеріалі практичних інженерних кейсів (діагностика збою
   в системі, вирішення конфлікту при злитті гілок, вибір архітектурного
   рішення), що поєднують кілька дисциплін у межах одного кейсу, з
   поясненням наслідків кожного вибору.
6. Конвеєр асинхронної генерації чернеток сценаріїв та тестових завдань
   засобами великої мовної моделі (Claude API), зокрема на основі
   лекційних матеріалів, завантажених викладачем, з обов'язковою
   модерацією (схвалення, редагування або відхилення) перед публікацією.
7. Дерево знань: візуалізація рівня засвоєння матеріалу у вигляді
   дерева (стовбур — флагманський модуль, гілки — курси різних
   викладачів, листки — теми) з кольоровою індикацією прогресу для
   студента (власне дерево) та викладача (дерево групи).
8. Флагманський навчальний модуль "Основи інженерії ПЗ" — банк фахових
   навичок без прив'язки до конкретної дисципліни чи дати іспиту
   (Git-воркфлоу, алгоритми та структури даних, мережі й протоколи,
   реляційні та нереляційні бази даних, основи безпеки OWASP та інші),
   що підтримується окремою "evergreen"-логікою повторення на основі
   серії послідовних днів практики (streak), а не датою складання.

## 5. Попередній інструментарій та технологічний стек

**Мови програмування та фреймворки**
JavaScript/TypeScript, React Native (Expo) — крос-платформний мобільний
застосунок з єдиною кодовою базою для iOS та Android; Node.js, Express —
серверна частина.

**Архітектурні патерни**
Клієнт-серверна архітектура з розділенням на синхронний REST API
(CRUD-операції, автентифікація) та асинхронну обробку фонових задач
через чергу повідомлень (генерація сценаріїв і тестів великою мовною
моделлю, парсинг лекційних матеріалів). Рольова модель доступу, що
прив'язана до сутності курсу (resource-based RBAC), а не глобально до
користувача.

**Бази даних**
PostgreSQL — основне реляційне сховище (користувачі, курси, теми,
результати тестів, SM-2-прогрес, розклад сесії, сценарії); Redis —
брокер черги повідомлень (BullMQ).

**Інтеграції**
Claude API (модель Haiku) — генерація чернеток навчальних сценаріїв та
тестових завдань з лекційних матеріалів за структурованим промптом;
Socket.io — двонаправлений обмін даними в реальному часі між клієнтом
викладача та сервером.

**DevOps-інструменти**
Docker та docker-compose — контейнеризація серверної частини, бази
даних та брокера черги для відтворюваності середовища розробки; GitHub
Actions — базовий CI-конвеєр (статичний аналіз коду, автоматичний
запуск тестів при кожному push).

**Безпека**
JWT (access + refresh токени) для автентифікації; шифрування з'єднань
(HTTPS, WSS); шифрування чутливих полів бази даних; обмеження частоти
запитів (rate limiting) на рівні API.
